=========================================================================================================
1. TOOLS (new, physlab2 only; nothing existing modified; all single-threaded)
=========================================================================================================
- xlab (xlab.cpp; ./build.sh xlab): interactive lab with save/restore of whole worlds (tee, hook, projectiles,
  reload). stdin: load PATH [N] | save K | restore K | in d j h f tx ty [n] | r <input-file line> |
  a d j h f deg [n] | p | loud | quiet | exp (all pending explosions: rt x y) | tp x y vx vy | gren | reload0 |
  sync. State line: S rt x y vx vy hook hx hy jumped grounded reload proj frz gren(0 none,1 got,2 active).
  build.sh links the existing build-sim objects of the *match* target. WARNING: build-sim's lab target
  objects are stale (lab.dir/sim.cpp.o Oct 2, sim.h changed Oct 3): new code linked against them reads
  CTasGame fields at wrong offsets (rt printed 21749). The old lab binary itself is self-consistent.
- xl.py (Python driver, writer thread; ~100k ticks/s incl. IO), hc.py ((1+lambda) hill climbing over per-tick
  [dir, jump, hook, fire, aim_deg]), gmodel.py (analytic pre-fire model, M6).
- b1_turn.py / b3_cut.py / b4_turn.py: turnaround optimisation (gate y<=Y climbing, x<=5376).
- c3_climb.py: climb optimiser scored by simulated double kicks (gmodel options -> pre-fire + point-blank +
  14-tick dir-1 tail -> estimated rt at x=5900). env KEEPFIRE, FIXM, NMAX, FROZEN.
- xrv (xrv.cpp): rendezvous beam: prefix ends right after the pre-fire step; reads the pending explosion
  (tick, point) and beam-searches hook/dir inputs to be next to it on the tick before, then tries
  point-blank aims (made exit_T1021).
- xbeam (xbeam.cpp): small beam to a Teero-track gate (projection on his smoothed track); d2_down.py:
  gate hill climbing (polished c3s3 to 1111).
- srvtrace.sh INPUTS OUT: real-server replay keeping the per-input trace. killpy.sh PATTERN: kill own python
  jobs (pkill -f PATTERN also kills the calling shell when its command line contains PATTERN).

M2. Point-blank wall kick geometry (m1_wallkick.py; spawn room, bare wall x=64, tee at rest, dir 0).
    The projectile starts at tee + 21*aim and moves 20 px per tick (+0.28 n^2 drop); its first segment is
    checked in the fire step, so a solid within ~41 px ALONG THE AIM explodes in the fire step itself, and
    the kick uses the tee position before the move. Kick = 12*(1-clamp((r-48)/87)) from the explosion to the
    tee centre; the explosion lies on the aim line => the kick is exactly opposite to the aim as long as the
    hit point is <= 48 px away. kick (x,y) / step of the explosion (1 = fire step); columns = aim offset
    from straight at the wall (+ = aimed down-left -> kick up-right):

M3. Jump and kick in the same tick: the jump SETS vy (-12 air / -13.2 ground) after the kick was added
    (projectiles tick before characters) -> the kick's vertical part is lost (m2_kickjump.py, tee (300,350),
    floor 34 px below, shooting down, start vy 6):

      kick, jump next tick -> -12.0 | jump, then kick next tick -> -12.0, then -21.59 (stacks).
      Side kick + jump same tick: vx kept (11.40, -12.0).
    lab: "quiet;in 0 0 0 0 0 -1 3;gren;reload0;tp 300 350 0 6;loud;in 0 1 0 1 0 1000" -> vy -12.0;

M4. Hook + kick: the 15 px/t hook limit is tested on the post-kick velocity (m3_hookkick.py; hook grabbed
    on the ceiling straight above):
      kick up off the floor: unhooked -11.5,-11.0,... | hooked -14.5 (pull still applied up to |v|=15), then
        only gravity;   kick right off the wall: unhooked (12.0,0.45) | hooked (12.0,-2.55), (11.86,-5.04),

M6. Pre-fire timing (gmodel.py; verified against xlab: fire from (5351,2294) at 260.40 deg -> model n=30,
    y 1933.7; xlab: explosion rt 1025 at (5247.3,1933.7); fire at 258.6 deg from (5357,2292) on the step to
    rt 995 -> model n=27 -> xlab explosion rt 1021 (5247.0,1947.6)).
    - A shot fired on input step m starts at the tee position BEFORE that step; its n-th 20-px segment is
      simulated in step m+n-1. The point-blank follow-up can be fired on step >= m+25, so a same-step
      double kick needs n >= 26.
    - Max rise 357 px (vertical, apex ~36 segments); 325 px after 25. At n = 26-31 the grenade climbs only
      2-5 px per segment, so 1 px of fire height costs ~0.25 tick of explosion time.
    - Face hits (x=5248, y 1921-1951) for a fire position x0=5350 [aims]:
        y0 2270: n 24-27 (257.8-259.5)  y0 2280: n 25-27  y0 2290: n 26-29 (258.9-260.2)
        y0 2300: n 28-31 (259.6-260.8)  y0 2310: n 30-33  y0 2320: n 34-36  y0 >= 2330: unreachable
      (x0 5300: aims 263.8-265.7; x0 5400: 251.6-257.8). Each n has a ~0.2-0.4 deg aim window: 64 fixed
      angles cannot hit it (the old NOTES' "0.1-0.3 deg window").
    => Fire the pre-fire from y ~2270-2290 (x ~5350) with n = 26-27, then climb ~13 px/t to arrive at
       x 5281-5300 next to the explosion point on the tick before it. Teero: y ~2285 at true ~993.8 ->
       explosion ~1018.6, consistent.

4. SUGGESTIONS FOR THE BEAM SEARCH
=========================================================================================================
1. Pre-grenade gate: never rank "grenade picked up earliest" (978 with vx 19 is ~7 ticks worse at y=2300
   and ~6-9 at the exit than 981 with vx ~5). Gate after the pickup: e.g. "y<=2290 climbing (vy<=-12),
   reload 0, x<=5376", or the exit tick, or x>=5671. Or: cut the pre-grenade run at rt ~960 and let the
   post-pickup search own the approach.
2. Always emit weapon 3 on the pickup tick (M1).
3. Exit macro (seg prefire=1 keeps pending explosions apart): when the tee is at y 2270-2320 near
   x 5300-5400 with reload 0, add the gmodel.face_hits aims for n = 26..31 (one aim per n, 0.02-deg
   precision). Reward being at x 5281-5300, |y - y_E| < ~10 on the tick before the explosion, with the
   point-blank fired so that it explodes in the same step (tee within ~41 px of the face along the aim,
   aim toward (5248, clamp(y-4,1922,1950))). xrv shows a rendezvous beam does this in ~20 s.
4. Hook pre-acceleration (<15 px/t) right before kicks (M4); jump BEFORE a vertical kick, never with it (M3).
5. Score the exit together with the next reload: exit kick + 25 should coincide with reaching the block
   (184,60) at x 5888-5952 (touch refills the jumps for the jump+floor kick at k~1075).
